今回の要件であれば、以下の仕様にするとシンプルかつ安全です。

## セッション管理仕様

### 1. 認証方式

認証には **WebAuthn** を使用します。

```text
WebAuthn Credential
        ↓
    本人確認
        ↓
   Session発行
        ↓
   Cookieに保存
```

WebAuthnのCredentialとSessionは別物として管理します。

---

### 2. ログイン時

WebAuthnによる認証に成功したら、新しいSessionを発行します。

```text
WebAuthn認証
    ↓
Credential検証
    ↓
User特定
    ↓
ランダムなSession Token生成
    ↓
DBにTokenのハッシュを保存
    ↓
Cookie発行
```

Session Tokenは暗号学的に安全な乱数から生成します。

DBには生のTokenではなく、ハッシュを保存します。

```text
Session
├─ id
├─ userId
├─ tokenHash
├─ createdAt
├─ lastUsedAt
└─ revokedAt
```

---

### 3. セッションCookie

Cookieは永続Cookieにします。

```http
HttpOnly
Secure
SameSite=Lax
Path=/
Max-Age=2592000
```

`Max-Age=2592000` は30日です。

これにより、**ブラウザを閉じてもCookieは残ります**。

したがって、翌日にブラウザを起動してアクセスしても、WebAuthnによる再ログインは不要です。

---

### 4. セッションの有効期間

セッションは**スライディング方式**にします。

つまり、

> 最後にアクセスしてから30日間アクセスがなければログインを要求する

という仕様です。

例えば、

```text
8/1   ログイン
      ↓
      Cookie有効期限：8/31

8/15  アクセス
      ↓
      Cookie有効期限：9/14

8/30  アクセス
      ↓
      Cookie有効期限：9/29
```

というように、アクセスするたびに有効期限を30日延長します。

---

### 5. Session ID自体は毎回変更しない

ここは重要です。

通常のアクセスでは、

```text
Session ID = ABCDEF...
```

を維持します。

アクセスごとに、

```text
Cookieの有効期限
lastUsedAt
```

だけを更新します。

**Session IDを毎回再生成する必要はありません。**

ただし、WebAuthnログインに成功して新しいログインセッションを作るときは、新しいSession IDを発行します。

---

### 6. サーバー側でも30日を検証

Cookieだけを信頼しません。

リクエストを受け取ったら、

```text
Cookie
  ↓
Session検索
  ↓
revokedAtを確認
  ↓
lastUsedAtを確認
  ↓
30日以上経過？
  ├─ YES → Session無効 → ログイン要求
  └─ NO  → 認証済み
```

とします。

つまり、**CookieとDBの両方でセッションの有効性を管理**します。

Cookieが何らかの理由で残っていても、DB側で失効していればログインできません。

---

### 7. ログアウト

ユーザーがログアウトした場合は、

```text
Cookie削除
     ↓
SessionをDB上で失効
```

とします。

単純にCookieだけ削除するのではなく、DB側のSessionも失効させます。

例えば、

```text
revokedAt = 現在時刻
```

とします。

---

### 8. 複数デバイス

ユーザーは複数のWebAuthn Credentialを持てるようにします。

```text
User
├─ WebAuthn Credential（PC）
├─ WebAuthn Credential（スマートフォン）
└─ WebAuthn Credential（タブレット）
```

さらにSessionもデバイスごとに独立させます。

```text
User
├─ Session（PC）
├─ Session（スマートフォン）
└─ Session（タブレット）
```

そのため、PCからログアウトしてもスマートフォンのSessionには影響しません。

---

### 9. デバイス追加

デバイス追加はメール招待方式にします。

```text
既存ユーザー
    ↓
デバイス追加を要求
    ↓
メール招待
    ↓
招待Token
    ↓
WebAuthn Credential登録
    ↓
新しいデバイス追加
```

招待TokenとSession Tokenは**完全に別物**として扱います。

また、既にログインしているユーザーがデバイスを追加する場合は、重要操作なので**既存のWebAuthnによる再認証**を要求するのが安全です。

---

## 最終的な動作

全体としては次のようになります。

```text
初回アクセス
    ↓
Session Cookieなし
    ↓
WebAuthnログイン
    ↓
Session発行
    ↓
Cookie（30日）発行
    ↓
──────────────────
通常利用
    ↓
Cookie送信
    ↓
Session DB確認
    ↓
lastUsedAtから30日以内
    ↓
ログイン済み
    ↓
Cookie期限を30日延長
lastUsedAt更新
──────────────────
```

30日間アクセスしなかった場合：

```text
アクセス
  ↓
Cookieなし/期限切れ
または
SessionのlastUsedAtから30日超過
  ↓
Session無効
  ↓
WebAuthnログイン
  ↓
新しいSession発行
```

そして、

```text
ユーザーがログアウト
        ↓
Session失効
        ↓
Cookie削除
```

となります。

### 推奨する最終仕様

| 項目              | 仕様                               |
| --------------- | -------------------------------- |
| 認証              | WebAuthn                         |
| Session         | DB管理                             |
| Session ID      | 暗号学的乱数                           |
| DB              | Session IDのハッシュを保存               |
| Cookie          | HttpOnly / Secure / SameSite=Lax |
| Cookie寿命        | 30日                              |
| Cookie方式        | 永続Cookie                         |
| 有効期限            | 最終アクセスから30日                      |
| アクセス時           | Cookie期限を30日延長                   |
| Session ID      | 通常アクセスでは変更しない                    |
| DB `lastUsedAt` | アクセスに応じて更新                       |
| 30日アクセスなし       | Session失効・WebAuthn再認証            |
| ログアウト           | Cookie削除＋Session失効               |
| 複数デバイス          | Credential / Sessionともに複数管理      |
| デバイス追加          | メール招待＋WebAuthn登録                 |
| 重要操作            | WebAuthnによる再認証                   |

この仕様なら、**「普段はログインを意識せず使えるが、1か月使わなければWebAuthnで再認証する」**という挙動になります。
